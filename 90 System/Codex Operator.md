## Structured-note convention

When a note needs database-like behavior, prefer YAML properties using the vocabulary already present in the vault:

```yaml
---
tags: []
type:
status:
area: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

Only add fields that have a real retrieval or workflow purpose. Existing notes do not need to be converted merely for consistency.

## Operator workflow

1. Capture the request or source material.
2. Locate related notes and links.
3. Update the smallest appropriate note, or create one descriptive new note.
4. Link only genuine relationships.
5. Verify frontmatter, embeds, fenced blocks, and internal links.
6. Report what changed and flag unresolved ambiguity.
