# Daily Workflow

## Ownership
| Record | Authoritative purpose |
| --- | --- |
| ClickUp task | Current company commitment, owner, due date, status and execution discussion |
| Monthly personal work report | Dated record of what happened, effort, outcomes, blockers and task references; input to the official monthly report |
| Obsidian project or knowledge note | Context, research, reasoning, lessons and links to tasks and official files |
| Calendar | Scheduled time and events |
| Official company storage | Approved reports, contracts and other canonical official files |

A dated checkbox records that day's view. Repeated entries are history, not separate commitments. Do not rewrite past entries when ClickUp changes. Resolve the current status in ClickUp; if an item has not been entered there, mark it as pending reconciliation rather than inventing an ID or assuming it synced.

## Daily reporting
Keep one personal report per month. Under each date record work performed, result, blocker or next step, and available ClickUp URL/ID or evidence link. Existing Persian and English entries and formatting remain valid. Use [[90 System/Templates/Workday Template]] for new sections if helpful.

## Month end
1. Preserve the original daily report.
2. Reconcile repeated task mentions by ClickUp ID/URL; check current completion status and flag unmatched items. Similar text alone is not proof of a duplicate.
3. Draft the official report with outcomes, completed work, ongoing work, blockers and decisions needed. Retain traceability to dates and task links.
4. Review and approve the draft before storing its canonical official copy; link that copy from the personal report.

ClickUp sync remains enabled, but this workflow does not establish that the plugin can synchronize arbitrary report checkboxes. Verify its mapping before importing or sending updates. Never treat a report mention as an automatic new task.

## Capture and gradual simplification
New unprocessed material goes to [[00 Inbox/Capture Inbox]]. Keep project-specific questions beside their project once triaged. Use global templates for new notes. Preserve imported structures and links; extract reusable knowledge into global Knowledge when useful and link it from the original project. Do not duplicate supplier evidence or bulk move the Catering collection.

## Minimal metadata
Use type and status when they help retrieval. Add source for provenance, reviewed for the date evidence was actually checked, and review_due only when a future recheck is needed. updated means edited, not verified. Existing reviewed_on fields remain valid until a relevant edit justifies migration; do not blanket-convert notes.

## Evidence and decisions
Follow [[03 Knowledge/Methods/Evidence, Interpretation and Decisions]]. Preserve sources, label inference, and record approval separately. Use [[90 System/Templates/Source Template]] and [[90 System/Templates/Decision Template]] where needed.
